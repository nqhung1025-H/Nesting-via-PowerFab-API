# Current result contract: HanlonNestResult/v1

The authoritative model is `src/Nesting/NestResultPackage.cs`. JSON uses the serializer
options in `LoadedNestResult.JsonOptions` in that file. This guide describes the
current v1.12 development snapshot; the contract identifier remains v1.

## Main result fields

`format`, `status`, `workOrderId`, `nestId`, `nestName`, `layoutSource`,
`nestImageFile`, `abeImport`, `layoutConditions`, `requisitionNumber`,
`autoRequisitionNumber`, `requisitionBatchId`, `targetPurchaseOrderNumber`,
`sheetNumber`, `material`, `parts`, `remnants` and `placements`.

Imported NC/SY2 preview data is not a completed save result until matching,
physical sheet selection and full geometry verification succeed. A completed
result is still submitted through the separate Save all nests action.

## Material and allocation

The material records shape, grade, thickness, length, width, units and source,
with stock identifiers and stock outlines when a real remnant is selected.
A new Purchase/Requirement material must not inherit allocated stock IDs,
remnant identity, holes or a previous remnant contour. Refer to
`src/Nesting/MaterialRequirements.cs` and `src/Geometry/StockGeometry.cs` for the validation rules.

## ABE provenance and placements

`abeImport` stores NC/SY2 source filenames and SHA-256 hashes, source program,
machine, original material information, linked PowerFab thickness and packers.
`geometrySource` identifies whether the completed import used the ABE NC/SY2
cutting paths or the older PowerFab drawing registration route. Current ABE imports
recover unique closed contours from NC burns inside each SY2 placement, with
up to 2 mm unambiguous holding micro-joints. Marks are excluded. Curved cut
sampling receives a 0.005 mm allowance without expanding shared straight cuts.
PowerFab part identities, sizes, quantities and material still have to match.
`powerFabThicknessMm` retains the resolved nominal PowerFab thickness. Both
4 mm and 5 mm may resolve from a numeric ABE setting of 4.5; an explicit filename
takes precedence, otherwise the matched PowerFab parts resolve the alias.
NC/SY2 profile letters are not a grade check. The original numeric profile
setting and source files are preserved, and reload validates the saved mapping.
The source positions and rotations are retained. Job quantities and placements
exclude packers; packers retain their own provenance and occupy material.
Original source files must remain available beside a saved JSON layout so load
and save verification can detect changed sources.
The loaded result retains its verified NC document for vector preview rendering.
That in-memory cache does not change the JSON contract or transmitted geometry.

ABE sheet and remnant names are the exact imported NC filename without its
extension, taken from `abeImport.programName`. For example,
`240175-02-PHASE90C-5MM` and `H0413-NFF-PHASE1-TYPEB-10MM-01` retain their
capitalization, spacing and suffixes. No normalization or batch renumbering is
applied. Names are independent of matched PowerFab material thickness and job
identity. Backend nest/remnant IDs still distinguish repeated source names.
The JSON keys remain `nestName` and remnant `name`; SaveNest uses the source
value in both `NestExtra1` and `RemnantName`, including when an unsent draft
contains an older generated name. Existing saved PowerFab records are not
renamed or resubmitted. Hanlon labels the value Sheet name. PowerFab owns the
native Remnant Name caption.

## Future remnants

`src/Geometry/RemnantGeometry.cs` keeps one rectangular right or bottom remnant, selecting
the larger valid usable area and retaining the right candidate on a tie.
Small bottom holding strips are excluded using the configured threshold,
100 mm by default. Existing stock contours, holes, spacing, packers, lead-ins
and skeleton cuts constrain the retained rectangle.

External remnant IDs are positive numeric identifiers generated by
`RemnantGeometry.NumericExternalId`; do not restore the obsolete GUID-R1 tokens.
Readable remnant names follow `NestNaming` independently of their identity.
Contour, area, bounding dimensions and the exported remnant DXF must agree.

## Saved state

Confirmed receipts prevent repeat submissions. Regenerating an already-saved
nest to change its geometry or identity is not a repair procedure. Refer to
`src/PowerFab/PowerFabNestApi.cs`, `src/Nesting/NestReview.cs` and the saved-state regression tests before
changing allocation, requisition numbering, receipt or TFS behavior.

## Sheet-report runtime (v1.12)

Optional `abeImport.processTime` records `seconds`, `dataName`, `reportName`,
`reportFile`, `reportSha256`, and 1-based `page`. It is populated by matching the
report Data Name against the imported NC/SY2 program, retaining the exact source
name. `abeImport.processTimeIssue` describes an unavailable or conflicting time.
The source PDF is copied as ABE-sheet-report.pdf and its hash is checked on reload.
The local source path and formatted display are not persisted JSON fields.
SaveNest uses `NestExtra2 = Process time: HH:MM:SS`; missing time omits that field.
The result PNG also displays the time; backend nest/remnant IDs and names are
unchanged. Saved receipts include the same optional `processTime` object.
